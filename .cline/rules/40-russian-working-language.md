# Russian Working Language

## Default language

Use Russian as the default language for communication with the repository owner.

Write in Russian unless the owner explicitly requests another language.

This applies to:

- Chat responses.
- Questions, clarifications and approval requests.
- Plans, progress updates and final reports.
- Frigga governance artifacts, including Project Passports, Gate Decision Packs,
  RAID-ED registers and Executive Status Updates.
- Comments and explanatory documentation intended for the owner.

## Preserve technical identifiers

Do not translate or alter:

- File paths, file names, directory names and URLs.
- YAML, JSON, TOML, XML, code, shell commands and configuration keys.
- API names, model IDs, environment-variable names and command-line flags.
- Git commands, branch names, commit hashes and version identifiers.
- Established technical abbreviations where translation would reduce clarity:
  API, CLI, IDE, Git, YAML, JSON, Markdown, MCP, RAID-ED, Gate, Baseline,
  Green, Yellow, Red and Uncertain.

Use Russian explanation around technical identifiers.

## Artifact language

Create new owner-facing project and governance artifacts in Russian by default.

For mixed-language artifacts:

- Keep technical labels and identifiers stable where needed.
- Add a Russian explanation the first time an English technical term appears.
- Preserve quoted source text in its original language.
- Do not translate code or data values.

## Language override

The owner may request English or another language for a specific response,
artifact, section or external audience. Apply that instruction only to the
specified scope; otherwise keep Russian as the default.
